## Problem

Every service had a different build/run pattern. Onboarding a new service took hours. Dev environments diverged from production.

## System Design

Multi-stage Dockerfiles with Alpine runtime. Compose files with health checks. Makefile targets: `build`, `up`, `down`, `logs`, `prune`. CI builds and pushes on git tag.

## Architecture Decisions

- Makefile as the single interface (not raw docker commands)
- `.env.example` committed, `.env` gitignored
- Health checks required in every compose service

## Tradeoffs

- Makefile is not cross-platform (team uses Linux/WSL)
- Convention over flexibility — new patterns need team agreement
- Multi-stage builds add Dockerfile complexity

## Production Behavior

CI fails if health check missing. Image size budget: 200MB for runtime images. Weekly `docker system prune` via cron.

## Lessons Learned

Standardize early. Docker chaos scales with team size.
