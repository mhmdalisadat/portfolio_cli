---
title: راه‌اندازی Redis Sentinel
description: لایه کش HA با failover مدیریت‌شده توسط Sentinel.
---

## Problem

کش session و rate-limiting به یک نود Redis وابسته بود. خرابی نود یعنی از دست رفتن کامل کش و sessionهای auth.

## System Design

۱ master، ۲ replica، ۳ نود Sentinel. کلاینت‌ها master را از Sentinel پیدا می‌کنند. persistence با AOF و `appendfsync everysec`.

## Architecture Decisions

- quorum Sentinel برابر ۲ برای تصمیم failover
- Redis exporter برای Prometheus
- Docker Compose برای هم‌ترازی dev با production

## Tradeoffs

- AOF everysec: تا ۱ ثانیه از دست رفتن داده در crash (برای کش قابل قبول)
- Sentinel سه پروسه اضافی برای مانیتور
- ریسک split-brain با تعداد فرد Sentinel کاهش یافت

## Production Behavior

failover خودکار در ~۱۰ ثانیه. کلاینت‌ها از Sentinel reconnect می‌کنند. هشدار memory در آستانه ۸۰٪.

## Lessons Learned

HA کش اختیاری نیست وقتی session در Redis است. قبل از نیاز، failover را برنامه‌ریزی کنید.
