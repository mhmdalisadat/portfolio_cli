## Problem

Python services were slow to start, memory-heavy, and lacked consistent health/metrics endpoints across the fleet.

## System Design

Single-binary Go services with HTTP + gRPC. Middleware for structured logging and request tracing. `/healthz` and `/readyz` for orchestrator probes. Prometheus metrics exported on `/metrics`.

## Architecture Decisions

- `context`-aware graceful shutdown on SIGTERM
- Database connection pooling via `pgxpool`
- No framework — stdlib + minimal dependencies

## Tradeoffs

- Less ecosystem magic vs Python/FastAPI
- gRPC adds proto maintenance overhead
- Smaller hiring pool for Go vs Python

## Production Behavior

P99 latency under 50ms for read endpoints. Error rate alert at 1%. DB pool exhaustion triggers scale-up.

## Lessons Learned

Observability is not optional infrastructure. Bake metrics and health checks into the first commit.
