## Problem

زیرساخت بدون مدل عملیاتی به دانش قبیله‌ای، پاسخ حادثه قهرمان‌محور و اتوماسیون شکننده تبدیل می‌شود.

## Observation

- آنچه قابل مشاهده نیست قابل بهره‌برداری نیست.
- شکست عادی است؛ برای کشف و بازیابی طراحی کن.
- تغییر بیش از سخت‌افزار خرابی ایجاد می‌کند.
- مستندات وابستگی زمان اجراست.

## Model

حلقه Operate: مشاهده → کشف → پاسخ → یادگیری. حلقه Build: طراحی → اتوماسیون → اعتبارسنجی → استقرار.

## Components

- **سیگنال‌های طلایی** — تأخیر، ترافیک، خطا، اشباع
- **Runbookها** — دانش رویه‌ای کدگذاری‌شده
- **محدودیت شعاع انفجار** — canary، rollout مرحله‌ای
- **پس‌مرتمه** — بدون سرزنش، عمل‌محور

## Rules

1. بدون مسیر rollback استقرار نکن
2. هشدار باید قابل اقدام باشد وگرنه بی‌صدا می‌شود
3. بار دوم را خودکار کن، نه بار اول
4. برنامه‌ریزی ظرفیت فرآیند پیوسته است

## Feedback Loops

**مثبت:** مشاهده‌پذیری بهتر → MTTR سریع‌تر → حادثه تکراری کمتر → زمان بیشتر برای اتوماسیون.

**منفی:** خستگی هشدار → سیگنال نادیده → outage طولانی → آتش‌سوزی واکنشی.

## Applications

- بهره‌برداری خوشه Kubernetes
- HA پایگاه داده (PostgreSQL، Redis)
- طراحی خط لوله CI/CD

## Limitations

- تیم‌های کوچک ممکن است زود بیش‌مهندسی کنند
- سرویس‌های مدیریت‌شده بار را جابه‌جا می‌کنند نه حذف

## Future Evolution

- بودجه خطای مبتنی بر SLO
- مهندسی آشوب به‌عنوان عمل استاندارد
